# ADR 005: APIのステータスと日本語エラー応答

## ステータス

採用。商品画像も[ADR 021](021-product-image-trpc.md)のtRPC形式を使います。

## 背景

入力不備・認証・認可・競合・内部障害を区別し、利用者へ一貫した日本語の説明を返す必要があります。
内部例外や上流応答の本文は公開しません。

## 決定

APIは言語に依存しない公開コードを返し、従来の安全な日本語文言を互換用として維持します。tRPCは標準のエラーコードとHTTP変換を維持し、
共通formatterで文言を整えます。画像操作も同じtRPCエラーコード・formatterを使います。

| 状況                     | HTTPステータス | tRPCコード            |
| ------------------------ | -------------- | --------------------- |
| 入力不備・不正なJSON     | 400            | BAD_REQUEST           |
| 未認証・無効な認証       | 401            | UNAUTHORIZED          |
| 権限不足                 | 403            | FORBIDDEN             |
| 対象・APIが見つからない  | 404            | NOT_FOUND             |
| 在庫不足・同時更新の競合 | 409            | CONFLICT              |
| 画像のサイズ超過         | 413            | PAYLOAD_TOO_LARGE     |
| 予期しない障害           | 500            | INTERNAL_SERVER_ERROR |

tRPCの入力検証は「入力内容が不正です。入力内容を確認してください」と返します。
予期しない障害は「処理に失敗しました。しばらくしてから再試行してください」と返し、
内部の例外文言やスタックは公開しません。サーバーログには障害の発生とコードを記録し、
入力・認証トークン・上流レスポンスの本文は載せません。

在庫Gatewayは上流の400・404・409を対応するApplicationErrorへ変換し、presentationがtRPCエラーへ対応させます。
それ以外の失敗は内部障害として扱い、上流の本文を利用者へ転送しません。
DOの入力は検証し、GET・DELETEやJSON解釈を含めた失敗もJSONの応答に変換します。
ドメインはHTTPやtRPCには依存しません。

## 選択肢

- ライブラリの既定応答を使う：英語や内部例外が混ざり、利用者向けの説明が不統一になる。
- API境界で応答を整える：tRPCの形式を保ちながら、HTTP・文言・公開範囲を揃えられるため採用。

## 影響と検証

- 単体のtRPCリクエストではコードに対応するHTTPステータスを返します。異なる結果を含む
  バッチリクエストはtRPC標準の207となる場合があるため、各結果のエラーコードを確認します。
- 在庫不足は409、未検出の在庫は404になります。
- クライアントはdata.errorCodeを翻訳し、API本文を直接表示しません。具体的な復旧説明はApplicationErrorのreasonを使います。詳細は[ADR 026](026-internationalization.md)。
- HTTPリクエストを使ったテストで400・401・403・404・409・413・500と内部情報の非公開を確認します。
- 詳細な障害追跡が必要な場合は、認証情報を含めない観測情報を別途設計します。
