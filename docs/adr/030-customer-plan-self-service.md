# ADR 030: 一般ユーザーの個人プランは本人が変更する

## ステータス

採用。ADR 020の運営による一般ユーザーへの割当方針を変更する。
企業プランは運営の企業一覧 → 企業詳細 → 基本設定で変更する。

## 背景

一般ユーザーの利用プランを運営が代理で変更する導線は、本人が選択するサービスの想定と合わない。
未設定や解除後にプラン権限を要求すると、本人が再選択する入口まで塞がる。

## 決定

- 一般ユーザーの「会員情報」に現在プランと変更・解除フォームを置く。登録済みの本人だけに表示する。
- `access.customerPlans` は本人の現在コードと一般ユーザー向け候補だけを返す。
- `access.changeCustomerPlan` はプランコード（解除はnull）だけを受け取る。対象ID・service・権限などの余分な入力は拒否する。
- サービス会員IDは認証済みsubjectから解決する。有効な会員とsubjectの一致を検証し、対象IDを本人に固定する。
- 会員種別ガードと現在登録状態の認可をミドルウェアで行う。プラン未設定でも操作できるよう、プラン由来の業務権限は要求しない。
- 変更に使う状態は認可前に読み、本人IDのスナップショットへ固定する。他の会員・企業・所属を業務処理へ渡さない。共通revisionで保存競合を409にする。
- 個人スナップショットを企業・platform・別ユーザーのスコープへ流用しない。一般ユーザー向けカタログにないコードと企業プランは拒否する。
- 個人プランの変更と監査は同じcommitで保存する。監査のactor・対象IDは本人、scopeはcustomer、actionはplan.changeとする。
- 運営のプラン一覧・割当APIは企業だけを対象とする。個人プラン用の運営ページ・ナビゲーションを除去し、旧URLは404にする。

## 範囲と影響

設定済みの開発用プランを選択する機能で、料金・決済・有料購読の実装は含まない。
将来有料プランを追加する場合は決済・購読状態のサーバー検証を設け、任意コードの選択だけで有料権限を付与しない。
一般ユーザーの公開ストア購入は引き続き個人プランの割当を前提にしない。
登録確認・退会・他サービスの資格、既存企業の権限上限を維持する。
