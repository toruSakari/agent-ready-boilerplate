# ドキュメントの作業ルール

- 日本語で、利用者が次に何をするか分かる文章を書く。
- 汎用の進め方は`project-guide.md`、Codexの設定と使い方は`codex-harness.md`に置く。
  プロジェクト固有の目的・用語・図は`project/`、設計判断は`adr/`に置く。
- 図はMermaidで記録し、矢印の意味を明示する。業務モデルと技術構成を区別する。
- 説明用の例、将来の構想、現在の実装を明示的に区別する。
- コマンドやパスは実ファイルと照合し、ローカルリンク・コードフェンス・整形を確認する。
- ADRには現在採用する設計のステータス・背景・決定・理由・影響を書く。文書は正しい現行実装を示し、過去の設計や変更経緯はGit履歴で確認する。
  実データの移行に必要なSQLマイグレーション、停止条件、復旧手順は保持する。
