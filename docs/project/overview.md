# プロジェクトの業務概要

この文書は現在のcommerceサンプルの業務概要です。別業務へ初期適用する場合は
[初期適用のガイド](../project-guide.md#別ドメインへの初期適用)に従い、利用者の要件から更新します。

一般ユーザー向けweb、企業担当者向けbusiness、運営向けadminを独立して配備し、共通APIとD1で注文・商品・企業を管理するサンプルです。

会員登録・退会はサービスごとに独立します。企業だけ登録した人は通常会員側では未登録で、
通常会員を退会しても企業担当者の会員・所属・ログインは残ります。
Clerkは共通の本人確認として使い、通常会員/registerの明示登録または対象サービスの招待承諾で会員を作ります。

各画面は共通の/api/trpcを使い、サービス会員・所属・操作権限をAPIで確認します。
URLの切替では権限を与えず、必要な手続きのservice入力で操作する会員を明示します。

## 利用者と画面の目的

| 利用者                   | 目的                                     | 画面の構成                                                           |
| ------------------------ | ---------------------------------------- | -------------------------------------------------------------------- |
| 一般ユーザー（通常会員） | 商品を探し、購入し、本人の注文を確認する | 商品一覧・検索、商品詳細、カート、購入確認、注文完了、注文履歴・詳細 |
| 企業担当者               | 自社の商品と受注を管理する               | ダッシュボード、注文管理、商品管理、メンバー、企業設定               |
| 運営担当者               | サービス全体の企業と利用資格を管理する   | ダッシュボード、企業管理、ユーザー管理、権限・プラン・アクセス設定   |

カスタマーの入口は商品一覧です。商品閲覧は未認証でも可能で、購入には有効な通常会員登録が必要です。
販売企業への所属や企業担当者の権限は購入条件にしません。企業所属を確認する管理APIと、
一般ユーザー向けの商品閲覧・購入APIは別の境界として扱います。

企業・運営のダッシュボードは状況の要約と次の作業への入口です。
一覧、詳細、編集、設定を専用ページへ分け、トップにすべてのフォームを並べません。
件数や状況の要約は実データから求め、一覧の一ページを全体件数として扱いません。

## 提供する範囲

現在の範囲は、サービス別会員、企業所属、ロール・操作権限、商品閲覧、カート、本人の注文、商品と複数画像、企業別在庫です。
カートは販売企業ごとに注文します。通常会員の注文では、商品価格と在庫をAPIで検証し、
他人の注文や停止企業への新規購入を拒否します。
一般ユーザーは企業所属を持ちません。企業作成は運営管理者に限定します。
決済連携はデモ用で、カード等への実課金は行いません。送料計算、配送先・配送追跡、レビュー、
広告、クーポン、外部への招待メール自動配送、無制限の企業セルフ登録、Clerkユーザーの自動削除は実装範囲に含みません。
画面上でも未実装の情報を架空の実績や実購入の機能として表示しません。
画面構成の判断は[ADR 028](../adr/028-commerce-storefront-and-dashboards.md)と
[サービスの調査](commerce-ux-research.md)を参照してください。

## 一覧から対象を見つける

注文は既存の状態・本人または企業のスコープ・日本時間の注文日、商品は名称・SKU、
在庫は台帳の在庫数、企業は利用状態・契約プランを条件にする。
検索条件をURLへ保存し、サーバーで全対象を絞り込んでからページを取得する。
調査・採用範囲・未決定事項は[一覧の調査](list-filter-research.md)を参照する。
