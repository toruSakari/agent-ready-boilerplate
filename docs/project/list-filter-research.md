# 一覧検索と状態絞り込みの調査

確認日：2026-10-11。新しい状態・カテゴリ・在庫警告の基準を追加する調査ではなく、既存データを見つける操作の調査。

## 採用する仕様

- 企業注文と本人注文履歴：既存のdraft／confirmed／shipped／completed／cancelled。注文番号の部分一致と開始・終了日。
- 商品：商品名・SKUの部分一致。新しい順／古い順。
- 在庫：商品名・SKUと台帳の在庫数が1以上／0。台帳がない商品は0。予約を差し引いた購入可能数とは区別する。
- 公開商品：商品名・SKU、台帳在庫、最低／最高価格。販売元が利用中の商品だけを返す既存制約を保つ。
- 企業一覧：企業名・利用中／利用停止・契約プラン／未設定。企業には登録日時がないため、ID順カーソルを使う。
- 条件はZodで検証しURLへ保存。変更時は先頭ページへ戻し、詳細から戻っても条件を復元する。
- サーバーで条件を適用してからDrizzleのカーソルで取得する。先頭25件だけのローカル検索を廃止する。
- 一覧の検索操作は取得境界の外へ置く。読み込み・失敗でも条件を変更できる。適用中の条件と解除操作を表示する。

## 採用しないこと・未決定事項

カテゴリ、公開／下書き／アーカイブ状態、在庫警告しきい値、ユーザーごとの保存ビューは現行モデルにない。
対応する業務ルールが決まるまで追加しない。企業の登録期間も保存日時がないため追加しない。
価格順・在庫数順の並び替えは日時順と異なるカーソル契約が必要なため、今回の並び替えは日時順に限定する。
一般ユーザーを企業に所属させたり、企業の注文検索へ一般ユーザーの個人情報を追加したりしない。

## 受け入れ条件

- 最初の25件にない商品・注文も検索結果に現れる。
- 状態と検索・期間を併用でき、該当なしと初期の空一覧を区別できる。
- 条件変更後に古いカーソルを送らない。URLを再読込み・履歴移動して同じ条件になる。
- 同時刻の対象を日時・IDで重複なく辿り、順序を逆転してもカーソルが成立する。
- 他企業・他会員の対象は条件を変更しても返らない。不正な状態・期間・数値をAPIでも拒否する。
- モバイル・ダーク・英語で検索操作、条件解除、Skeletonが使える。
