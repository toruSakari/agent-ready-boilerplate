# 検証ガイド

検証は現在の変更内容と実行環境に対して行います。過去の成功結果を、未実行の変更や本番環境の保証に使いません。
Nodeは`.nvmrc`、pnpmはルートの`package.json`に指定したバージョンを使います。

## 基本コマンド

```sh
pnpm install --frozen-lockfile
pnpm check
pnpm typecheck
pnpm test
pnpm test:harness
pnpm build
```

`check`は整形・lint・型、`test`は単体・結合、`test:harness`は開発ハーネスを確認します。
`typecheck`は共通コードと各アプリを独立したTypeScript programで検査し、サービスごとのRouter型も確認します。
`build`はAPI公開型の生成、APIのdry-run、web・business・adminのビルドを行い、実配備はしません。
文書のみの変更では整形・ローカルリンク・コードフェンス・Mermaidを確認します。

変更内容に応じて次も実行します。

- 画面・通信フロー：`pnpm test:e2e`。実ローカルAPIの検証とブラウザー操作の検証を区別する
- 多言語の設計・変更：[多言語の受け入れ条件](../project-guide.md#多言語の表示とapi契約)から対象locale・fallback・整形・SSR分離など必要な検証を選ぶ。設計上の想定と実装済みの範囲を区別する
- Storybook：`pnpm test:stories`、`pnpm build-storybook`
- 公開API型：`pnpm api:types`。生成物を直接編集しない
- 独立リポジトリの切り出し：`pnpm repository:export <対象> --out <出力先>`。詳細は[切り出し手順](../repository-split.md)に従う

## 現行サンプルの重要な確認対象

以下の会員区分・操作・容量は現在のサンプルの契約です。別業務では用語・actor・上限を要件から定め、
成功だけでなく未認証・権限不足・他所有者／他tenant・競合・再実行・失敗時の副作用を検証します。
既存の操作を残す場合は、その拒否条件と上限を維持します。

- 全RPCの公開契約、未定義APIの404、本人確認と各操作の会員・現在権限・入力検証の順序
- サービス別会員、他企業拒否、顧客の本人注文、運営Access、失効後の拒否
- Accessの状態版と競合時の409、招待・退会・再登録、最後の管理者保護
- 注文・在庫・決済の再送、途中失敗、OutboxとQueueの重複防止
- 画像のFormData入力、認可前に本文を読まないこと、実バイト数6MiB・画像本体5MiBの上限
- 画像取得の単独呼び出し、非公開キャッシュ、他企業拒否、R2とD1の補償・清掃
- 本人・会員・企業の切替時のキャッシュ分離と遅延応答、object URLの解放

画像の詳細は[ADR 021](../adr/021-product-image-trpc.md)、環境準備とDB移行は[配備手順](../cloudflare.md)を参照してください。

- 一覧検索をLIMITより前に適用すること、状態・期間・価格の併用、同時刻と境界削除後のカーソル
- 検索条件のURL復元、条件変更時のページリセット、取得失敗中の操作と復旧、モバイル・英語・ダーク表示

## 結果の扱いと既知の注意点

実行したコマンド、対象、結果、警告、未実行項目は変更の完了報告やPRに記録します。
全体成功・対象限定の成功・未実行を区別し、失敗をチェックの無効化や根拠のないtimeout・retry緩和で隠しません。

- 在庫統合テストの大量IDケースは実行環境の負荷で既定5秒を超えることがあります。
  タイムアウト後の後続ケースにDBの一意制約エラーが出た場合も、全体成功とは扱わず、隔離実行と原因調査を行います。
- TanStack Start・Clerkのchunkサイズ、Storybookのchunkサイズなど、上流由来の診断が出る場合があります。
  原因と影響を確認し、アプリの問題と区別して報告します。
- Wranglerのproxy通知・scheduledの未自動実行、開発用evalの診断は実行環境と開発モードに依存します。
  定期処理の自動発火や本番動作まで検証できたとは見なしません。
- ブラウザーを起動できない環境でのHTTP検証は、実ブラウザーE2Eの代わりにはなりません。
  ローカル成功から公開CI、実Clerk・Cloudflare Access、本番リソースへの疎通成功を推定しません。
