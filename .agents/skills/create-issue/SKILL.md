# 再現と判断ができるIssueを作る

1. ルートと対象パスのAGENTS.md、依頼内容、既存の関連Issueを読む。
   [PR・Issueの共通手順](../../../docs/project-guide.md#prとissueの作成)で対象と公開範囲を確認する。
2. 不具合は[バグ報告](../../../.github/ISSUE_TEMPLATE/bug_report.md)、機能追加は
   [機能提案](../../../.github/ISSUE_TEMPLATE/feature_request.md)の本文を正本として使う。
   不具合は再現手順・期待と実際・環境・影響、提案は困りごと・利用者の価値・範囲・受け入れ条件を具体化する。
   不明な条件は質問または未確認とし、原因・重要度・実装済みの挙動を推測で補わない。
3. UIの挙動には共通手順の[操作の証拠](../../../docs/project-guide.md#操作の証拠を用意する)を適用する。
   未実装の提案は現在の困りごとを示し、将来案の画像は実動作と区別する。動画だけで再現手順を済ませない。
4. 下書き依頼ならローカル本文と未確認事項を返す。公開を依頼されている場合だけ
   [公開と結果確認](../../../docs/project-guide.md#公開と結果確認)へ進み、作成先・本文・添付を読み戻す。
   未依頼のlabel・assignee・milestone・project・メンションは加えない。Issue作成から実装修正へ自動で進まない。
