# 新しい業務を始める

1. ルート・対象パスのAGENTS.md、git status、既存の`docs/project/`を確認し、
   [初期適用のガイド](../../../docs/project-guide.md#別ドメインへの初期適用)を読む。
   現行サンプルの拡張か、別業務への適用かを依頼と既存文書から判断する。作業を左右する不明点だけ質問する。
2. [domain-design](../domain-design/SKILL.md)を使い、新しい要件の用語・境界・actor・所有者・tenant・権限を整理する。
   既存の用語、会員区分、画面構成を既定値にせず、初期適用のガイドに従って残す／置き換える／今回使わない範囲を記録する。
   画面・通知などの表示がある場合は[多言語の設計](../../../docs/project-guide.md#多言語の表示とapi契約)も確認し、
   対応言語・既定言語・地域設定と、今回実装する範囲を決める。
3. 設計のみの依頼なら文書・最初の受け入れ条件・未決定事項を報告して止める。
   実装も依頼されていれば[implement-use-case](../implement-use-case/SKILL.md)へ引き継ぐ。
   認可やデータ境界が未決定の部分は止め、既存の安全な範囲を保つ。
4. 差分、確認結果、未実行の検証と残る判断を報告する。初期適用は削除・公開・配備や権限設定変更の許可ではない。

このSkillは設計用の別フレームワークやコード生成器を追加しない。
Entity・VO・Repository・UIは対象ユースケースに必要なものだけ選び、既存規約と保存境界を守る。
