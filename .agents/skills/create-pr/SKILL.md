# 変更と検証が伝わるPRを作る

1. ルートと対象パスのAGENTS.md、git status、依頼内容を確認する。
   本文の下書きとGitHub上のDraft PRを区別し、後者も外部公開として扱う。
2. [PR・Issueの共通手順](../../../docs/project-guide.md#prとissueの作成)を読み、
   対象リポジトリ・公開範囲・base/head・既存PR・差分と検証結果を確認する。
3. [PRテンプレート](../../../.github/pull_request_template.md)を正本に、日本語で理由・変更・影響・
   検証・レビューしてほしい点を埋める。コミット一覧を説明の代わりにせず、未確認事項を明記する。
4. UIの不具合修正・機能追加は共通手順の[操作の証拠](../../../docs/project-guide.md#操作の証拠を用意する)を適用する。
   実際の操作動画と必要な画像を用意し、録画不可・比較未実施も正直に記録する。
5. 公開を依頼されている場合だけ、共通手順の[公開と結果確認](../../../docs/project-guide.md#公開と結果確認)に従う。
   既定はDraft。作成先・base/head・本文・添付の実物と検証状態を読み戻してURLを報告する。
   未依頼のマージ・配備・reviewer追加はしない。
